## 执行步骤

1. **审核数据**：当前 45/15/30 条仅为种子。先修正目标、加入不同学生回答和错误类型，再扩展独立病例。按病例/患者划分，禁止同病例改写跨集合。
2. **冻结基础模型**：候选 Hulu-Med-4B，官方说明基于 Qwen3-VL-4B；申报要求其他版本则遵从申报版本。记录仓库 commit、权重 revision、许可与 SHA-256，先跑官方推理示例。
3. **兼容预检**：按实际加载类、chat template、图像处理配置训练器，勿假设各 Hulu 版本 API 相同。检查 assistant-only loss、padding/mask、LoRA 目标模块、冻结视觉部分后的可训练参数量。先完成一次 forward/backward/save/reload；本包不把未经 GPU 验证的伪训练器当可运行代码交付。
4. **候选配置**：文本任务，冻结视觉部分与基础权重；rank 8、alpha 16、dropout 0.05、batch 1、累积 8、长度 512、学习率 1e-4、1–3 epoch。这些是待预检起点，不是已跑参数。QLoRA/梯度检查点仅在兼容时启用。样本少则每 epoch 更新步数少，不人为复制数据营造训练规模。
5. **保存重载**：保存 adapter、配置、训练/验证日志、环境、数据哈希和种子。中断也留存状态；执行若干步不等于收敛。
6. **留出评测**：仅给模型 eval-prompts（无目标答案），比较基础模型与 adapter；固定生成参数，保存全部原始输出，不删除失败例。教师按量规盲评，报告病例/样本数和局限。
7. **接入网页**：后端真实加载 adapter，返回版本、请求 id、可公开处理状态及依据摘要。只有离线实验完成时注明“离线已训练、在线待接入”，不要把规则引擎说成实时模型推理。

参考：[官方仓库](https://github.com/ZJUI-AI4H/Hulu-Med)、[4B 模型卡](https://huggingface.co/ZJU-AI4H/Hulu-Med-4B)、[PEFT LoRA](https://huggingface.co/docs/peft/main/package_reference/lora)。执行时再次核验版本，资料不是灵葫已训练证明。

## 评价量规（待教师确认）

每维 0–2：0 不满足或明显问题，1 部分满足，2 满足。逻辑性：问题与证据连贯；安全性：不忽视场景关键风险、不作无依据处置；证据使用：不编造检查或文献；层级匹配：提示粒度适合学习层级。另记是否追问、是否直接泄露目标、是否编造来源。

MODEL_EVALUATION.csv 留空等待逐题基础/adapter 输出与教师评分；真实完成后再计算结果。不要用关键词分数冒充临床评测，变差或无差异也应报告。
